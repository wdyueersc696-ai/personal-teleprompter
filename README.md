# Личный телесуфлёр для Reels и видео

Мобильный телесуфлёр без аккаунта, сервера и облачного хранения сценариев. Он открывается по ссылке, устанавливается как PWA и после первого успешного открытия работает без сети.

**Открыть приложение:** https://wdyueersc696-ai.github.io/personal-teleprompter/

Приложение сделано на обычных HTML, CSS и JavaScript. Runtime-зависимостей и обязательной сборки нет.

## Что уже работает в MVP

- ввод сценария, подсчёт слов и оценка времени чтения;
- плавная автопрокрутка через `requestAnimationFrame` со скоростью `50–400 WPM`;
- размер текста `28–96 px`, межстрочный интервал `1.10–2.20` и ширина колонки `50–100%`;
- отсчёт перед стартом: выключен, 3 или 5 секунд;
- пуск, пауза, продолжение, начало с нуля, перемотка на 5 секунд и ползунок позиции;
- прогресс, прошедшее и оставшееся время;
- изменение скорости и размера текста прямо во время чтения без сброса позиции;
- центральная фокус-зона, зеркальный режим, тёмная и светлая темы;
- портретная и альбомная ориентации без принудительной блокировки;
- автоматическое скрытие панели управления через 2,8 секунды чтения;
- безопасное одиночное касание свободной области для показа или скрытия панели; свайпы и длительное нажатие не запускают скрытых команд;
- ручная прокрутка на паузе с синхронизацией позиции; во время воспроизведения прямой touch-scroll заблокирован;
- автоматическая пауза при сворачивании вкладки и защита от скачка после длинного пропущенного кадра;
- Fullscreen API с запасным сценарием установки на главный экран;
- Screen Wake Lock как необязательное улучшение: отсутствие поддержки не блокирует чтение;
- автосохранение текста и настроек в `localStorage`, восстановление после перезагрузки и безопасный сброс повреждённых данных;
- устанавливаемая PWA, локальный app shell, офлайн-запуск и управляемое обновление;
- базовая доступность: семантические подписи, live-region, видимый клавиатурный фокус, сенсорные цели и поддержка `prefers-reduced-motion`.

Автоматические тесты проверяют расчёты, локальное состояние, движок прокрутки, состояния чтения, Fullscreen/Wake Lock-адаптеры, manifest, иконки, service worker и локальный сервер. Реальные браузеры и физические телефоны проверяются отдельно по [MANUAL-QA.md](./MANUAL-QA.md).

## Важное ограничение съёмки на том же iPhone

Этот MVP не записывает видео и не может оставаться поверх приложения «Камера», Instagram или другого приложения на iPhone. При переключении со страницы суфлёр ставится на паузу.

Для съёмки сейчас нужен один из вариантов:

- второй телефон или планшет для текста;
- отдельная камера;
- физическое телесуфлёрное стекло с зеркальным режимом.

Если суфлёр и запись камерой должны одновременно работать на одном телефоне, нужен встроенный рекордер внутри приложения. Это задача второй версии, а не функция текущего MVP.

## Быстрый запуск на Windows

Нужен установленный актуальный LTS-релиз Node.js. Устанавливать npm-пакеты не требуется.

В PowerShell из корня проекта:

```powershell
npm.cmd test
npm.cmd run serve
```

Откройте в браузере:

```text
http://127.0.0.1:4173
```

Не открывайте `index.html` двойным щелчком через `file://`: Service Worker и часть PWA-возможностей так не работают.

## Как пользоваться

1. Вставьте текст на стартовом экране.
2. Выберите скорость, размер текста, межстрочный интервал, ширину, отсчёт и режимы экрана.
3. Нажмите «Запустить суфлёр».
4. Разрешите полный экран, если браузер запросит разрешение.
5. Во время чтения используйте центральную кнопку, перемотку, ползунок или горячие клавиши.
6. Для ручной прокрутки сначала поставьте чтение на паузу.
7. Нажмите «← Текст», чтобы вернуться к редактору.

Текст и настройки сохраняются автоматически примерно через 250 мс после изменения и дополнительно при сворачивании или закрытии страницы. Новый запуск из редактора и перезагрузка намеренно начинают чтение с начала.

## Горячие клавиши

Горячие клавиши работают в режиме чтения, когда фокус не находится в поле ввода или ползунке.

| Клавиша | Действие |
|---|---|
| `Space` | Пуск или пауза |
| `R` | Начать сначала |
| `F` | Войти в полный экран или выйти из него |
| `M` | Включить или выключить зеркало |
| `↑` | Увеличить скорость на 5 WPM |
| `↓` | Уменьшить скорость на 5 WPM |
| `←` | Назад на 5 секунд |
| `→` | Вперёд на 5 секунд |

## Открытие на телефоне в локальной сети

Запустите сервер на всех сетевых интерфейсах:

```powershell
npm.cmd run serve -- --host 0.0.0.0
```

Узнайте IPv4-адрес компьютера командой `ipconfig`, затем на телефоне в той же Wi-Fi-сети откройте:

```text
http://<IPv4-компьютера>:4173
```

Если Windows спросит разрешение для брандмауэра, разрешайте доступ только для доверенной частной сети.

Важно: адрес вида `http://192.168.x.x:4173` не является `localhost` для телефона. Установка Service Worker, офлайн-режим, Wake Lock и другие защищённые API обычно требуют HTTPS либо настоящего `localhost`. LAN-адрес по HTTP подходит для быстрой проверки интерфейса, но для полной PWA-проверки используйте HTTPS-деплой.

## Бесплатный статический деплой

У проекта нет шага сборки. Публиковать нужно каталог, в корне которого находится `index.html`. Все runtime-ссылки относительные (`./...`), поэтому приложение работает как в корне домена, так и в подпапке, например GitHub Pages.

Бесплатные тарифы и их лимиты могут меняться; перед публикацией проверьте актуальные условия выбранного сервиса.

### 1. GitHub Pages

1. Создайте репозиторий и отправьте в него проект.
2. Откройте `Settings → Pages`.
3. В `Build and deployment` выберите `Deploy from a branch`.
4. Выберите нужную ветку и каталог `/ (root)`.
5. Откройте выданный HTTPS-адрес вида `https://<user>.github.io/<repo>/`.

Относительные `start_url`, `scope` и ссылки на файлы сохраняют работу PWA внутри подпапки репозитория.

### 2. Cloudflare Pages

1. В панели Cloudflare откройте `Workers & Pages → Create → Pages`.
2. Выберите Direct Upload.
3. Загрузите папку или ZIP так, чтобы `index.html` находился на верхнем уровне публикации, а не внутри дополнительной папки-обёртки.
4. После деплоя откройте выданный адрес `*.pages.dev` по HTTPS.

Альтернатива — подключить Git-репозиторий без build-команды и публиковать корень проекта.

### 3. Netlify Drop

1. Откройте [Netlify Drop](https://app.netlify.com/drop).
2. Перетащите каталог проекта, содержащий `index.html` в корне.
3. Дождитесь выдачи HTTPS-адреса `*.netlify.app`.

Для обновления повторно загрузите тот же проект либо подключите Git-репозиторий. Build command не нужен; publish directory — корень проекта.

### 4. Vercel

1. Импортируйте Git-репозиторий в Vercel.
2. Выберите `Framework Preset: Other`.
3. Оставьте Build Command пустой, Root Directory укажите как корень проекта, Output Directory — `.`.
4. Опубликуйте проект и откройте выданный HTTPS-адрес `*.vercel.app`.

После любого деплоя проверьте, что по прямым адресам открываются `manifest.webmanifest`, `sw.js` и файлы из `icons/`, а затем выполните офлайн-сценарий из [MANUAL-QA.md](./MANUAL-QA.md).

## Установка на iPhone или iPad

1. Откройте HTTPS-адрес приложения именно в Safari.
2. Дождитесь полной первой загрузки.
3. Нажмите «Поделиться».
4. Выберите «На экран “Домой”» или «Добавить на экран “Домой”» — название зависит от версии iOS.
5. Если система показывает параметр «Открывать как веб-приложение», оставьте его включённым.
6. Нажмите «Добавить» и запускайте суфлёр новой иконкой с главного экрана.

На iPhone Fullscreen API для обычной страницы может быть недоступен. Установка на главный экран — предусмотренный запасной сценарий, но она не даёт приложению права отображаться поверх «Камеры».

## Установка на Android

1. Откройте HTTPS-адрес в Chrome.
2. Дождитесь полной первой загрузки.
3. Откройте меню `⋮`.
4. Выберите «Установить приложение» либо «Добавить на главный экран».
5. Подтвердите установку и запустите приложение с новой иконки.

Формулировки меню зависят от версии Chrome и оболочки производителя.

## Приватность и данные

- Сценарий не отправляется приложением на сервер и не включается в URL.
- В поле сценария отключена встроенная проверка правописания, чтобы браузер не передавал текст внешней службе проверки.
- Текст и настройки хранятся в `localStorage` текущего браузерного профиля для конкретного домена.
- В PWA-кэш попадают только файлы интерфейса и кода, а не отдельная облачная копия сценария.
- Аналитики, трекеров, аккаунтов и API для пользовательских данных в проекте нет.
- Статический хостинг всё равно получает обычные технические данные HTTP-соединения, например IP-адрес и запросы файлов приложения. Содержимое введённого сценария код проекта ему не передаёт.
- Очистка данных сайта, удаление профиля браузера или сброс устройства удалит локальную копию. Для важного текста храните оригинал отдельно.

Чтобы удалить сценарий из приложения, очистите поле и дождитесь надписи «Сохранено на устройстве». Для полного удаления используйте очистку данных сайта в настройках браузера.

## Офлайн-режим и обновления PWA

Офлайн-запуск доступен после первой успешной онлайн-загрузки по HTTPS или через `localhost`, когда Service Worker успел установить app shell. Перед поездкой или съёмкой один раз откройте приложение онлайн, затем проверьте его в авиарежиме.

При обнаружении нового Service Worker приложение показывает сообщение «Доступна новая версия». Проверка также повторяется после возврата приложения на экран и восстановления сети. Нажатие «Обновить» активирует новую оболочку и перезагружает страницу. Сохранённый текст и настройки остаются в `localStorage`.

При выпуске новой версии разработчику нужно увеличить суффикс `CACHE_NAME` в `sw.js`, например `teleprompter-shell-vN` → `teleprompter-shell-vN+1`, и заново задеплоить все файлы одновременно. Если уведомление не появилось, откройте приложение онлайн и один раз перезагрузите страницу.
